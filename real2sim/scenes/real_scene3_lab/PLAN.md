# real_scene3：实验室操作台 建模说明

v3（2026-10-23），依据四张手机照片（`reference/p1–p4.jpg`），围着同一张白色折叠培训桌各拍一张。v1 只建了操作台，房间里的家具都压平在墙面照片上；v2 把工位桌、椅子、柜子也建成了立体模型；v3 去掉墙面照片贴图，墙改成纯色饰面加门、白板、电视，角落里那台 G1-D 直接放了一台 G1-D 模型。场景变更时同步更新本文件。

## 文件

| 文件 | 作用 |
| --- | --- |
| `fit_photo.py` | 四张照片上手工标的角点和边线，联合反求四台相机的位姿、共享焦距和桌子尺寸，写 `fit_photo.json` |
| `build_scene.py` | 读 `fit_photo.json`，生成 `usd/`（`background.usda`、`table.usda`、`lights.usda`、`scene.usda`、角落 G1-D 的静态层 `g1d.usdc`、桌面 / 挡板 / 地毯贴图）和 RoboDojo Room 入口 `real_scene3.usd`。家具的摆放和尺寸在 `FURNITURE` 里，墙面在 `WALL_SPANS`、`DOOR`、`BOARDS`、`TV` 里，G1-D 在 `G1D` 里 |
| `check_scene.py` | 离线检查，写 `check_report.json`（24/24 通过） |
| `preview.py` | numpy 光栅化预览（`preview/`）。`compare_photo.jpg` 每行是：照片、拟合相机下的渲染、模型边缘叠在照片上（操作台红色，家具绿色）；只核对几何和贴图，不代表 RTX 效果 |

运行（本机无 Isaac 也可）：

```bash
uv run --no-project --python 3.11 --with usd-core --with trimesh --with numpy --with shapely \
    --with opencv-python-headless --with scipy --with mapbox-earcut --with manifold3d --with fast-simplification \
    sh -c "python fit_photo.py && python build_scene.py && python check_scene.py && python preview.py"
```

## 坐标系

与 real_scene1/2 一致：Z 向上，米制；原点在桌面中心正下方的地面；+X 沿桌子长边，+Y 指向挡板。机器人站在没有挡板的 −Y 一侧、面向 +Y。桌面前沿 y = −0.343。

四张照片的拍摄位置：p1 在挡板一侧（+Y）、p3 在机器人一侧（−Y）、p2 在 +X 端、p4 在 −X 端。依据是走线盒靠近挡板一侧的桌沿，并且四张照片里的背景能互相对上（例如抽屉柜和机器人在 p2 的右侧、p3 的左侧）。

**假设：** 机器人站在开放的一侧，底盘才能伸进桌下。如果真机实际站在挡板一侧，把 Room 绕 Z 轴转 180°。

## 尺寸与置信度（`fit_photo.json`）

共用了约 60 个点和 6 条线做约束，桌面、走线盒、挡板的点误差大多在 0.3–4 px。脚轮位于暗处，取点误差较大：有一个脚轮在 p2 和 p3 中都偏了约 20 px，它只影响脚轮的装饰几何。

| 项 | 取值 | 依据 | 置信度 |
| --- | --- | --- | --- |
| 桌面高 | 0.749 m | **尺度基准**：先验 0.75 ± 0.015（标准培训桌高度） | 中 |
| 桌面长 × 宽 | 1.369 × 0.686 m | 拟合；与常见规格 1.4 × 0.7 m 相差约 2% | 中 |
| 板厚 | 21 mm | 四张照片的桌沿立面 | 中 |
| 走线盒 | 0.25 × 0.11 m，中心 (−0.006, +0.217) | 四张照片的四个角 | 中高 |
| 挡板 | 长 1.19 m，在 y = +0.293（比桌沿缩进 5 cm），底边离地 0.456 m，上沿到桌板底面 | p1 的两个底角，p2、p4 的端部 | 中 |
| 立柱 | 竖直，x = ±0.638，y = +0.081（偏向挡板一侧） | p3 两根立柱的中线、p2 和 p4 的端视图。v1 按 p1 的四条线拟合成外倾 15° 的斜腿，那几个点其实落在 V 形底脚上（10-22 用户指出腿是直的） | 中 |
| 脚轮 | (±0.623, ±0.238) | 暗处取点，误差 5–20 px | 低 |
| 立柱截面、V 形底座、桌板下的横梁和托架 | 0.05 × 0.06 m 等 | 目测；横梁在照片里看不到，是折叠桌翻板结构的推测 | 低 |
| 墙 | x ∈ [−2.9, 3.3]，y ∈ [−2.45, 3.8]，高 2.8 m | 墙脚像素经拟合相机反投影到地面；高度没有拍到 | 低 |

尺度只依赖“桌高 0.75 m”这一个假设。如果这是标准的 1.4 × 0.7 m 桌子，整体应放大 1.022 倍（桌高变为 0.766 m）。

## 需要实测的尺寸（卷尺 5 分钟）

1. 桌面长、宽、离地高度、板厚（任意一个都能定尺度）。
2. 挡板底边离地高度、到桌沿的缩进。
3. 两根立柱在桌板下的间距，以及立柱到机器人一侧桌沿的距离（决定底盘能伸进多深）。

量到之后，整体比例不对就用 `build_scene.py --scale-correction` 缩放；单个尺寸不对，就在 `fit_photo.py` 里把对应先验的 sigma 调小，固定成实测值，重新拟合。

## 房间家具（v2）

15 件参数化模型加 1 台 G1-D，全部是静态的，放在 `background.usda` 的 `/Background/Furniture/<类>_<序号>` 下，每件带盒体或小凸包碰撞体（purpose 为 guide）。平台 3D 预览的「隐藏房间」也会一起隐藏它们。

**定位方法。** 相机沿用 `fit_photo.json` 的拟合结果，不重新拟合。在放大加网格的照片上手标家具的落地点（桌脚、椅脚、柜底边），用拟合相机反投影到地面 z = 0；两张照片都能看到的（铁皮柜的底边和把手）做三角化。高度方向只用来检查：沿落地点的竖直线读顶边的高度。摆放好之后，用 `preview.py` 的绿色边线和照片逐件比对，再微调。尺寸取常见规格，再用照片核对。

**照片之间对不上的地方。**

- p2 的相机在画面边缘外推不准：按它反投影，西墙相对桌子转了约 13°（p3 看北墙只转 1.5°），远处的高度也偏低约 5 cm。所以西侧家具按与墙平行摆放，只取 p2 的大致位置。
- 北排最右那张桌子：p3 给出的前沿是 y ≈ 3.05，p4 要求 y ≈ 2.45，否则桌角会落到墙外。差 0.6 m，不能用噪声解释，可能是东墙北段比拟合的 x = 3.3 更远。机器人主要朝 +Y 看，所以按 p3 摆。p4 左缘这张桌子和两把椅子在 `HAND_MASK` 里手标了一个多边形，从东墙贴图里抠掉。
- 椅子带脚轮，几张照片之间可能被挪动过。

**墙面（v3）。** 不再贴照片（10-23 用户要求）。墙面是纯色饰面，颜色取照片的 sRGB 中值，和原来的照片贴图一样直接当反照率；位置由照片像素经拟合相机反投影到墙面得到：

| --- | --- | --- |
| 南（−Y，p1） | x > 1.30 白墙，−1.56…1.30 玻璃隔断（不透明的绿灰色，后面没有建模），x < −1.56 白墙 | 4 根黑色竖框和底框；白门 x −2.77…−1.87、高 2.1 m（−X 侧门边在照片外，按 0.9 m 宽的门推），黑把手离地 1.0 m |
| 北（+Y，p3） | 白墙 | 黑边白板 x −1.35…1.16，下边框离地 1.29 m；白板下挂一块黑屏 x 0.20…0.99，z 1.03…1.27 |
| 西（−X，p2） | y < 2.5 深灰吸音板（带 5 cm 黑踢脚线），y > 2.5 白墙（G1-D 背后） | 黑边白板 y −2.07…2.48，下边框离地 1.08 m |
| 东（+X，p4） | 深灰吸音板（带踢脚线） | 黑边白板 y −2.13…2.91，下边框离地 1.08 m |

## 资产分层

- **`table.usda` `/Table`**：
  - 桌面：圆角板（封边材质）加一层贴图面；贴图是四张照片矫正后的逐像素中值（去掉单张照片的反光和阴影），保留真实桌面上的浅色网格胶带线和走线盒；
  - 灰色带横肋的挡板，贴图取 p1 的行剖面；
  - 两根竖直立柱、V 形底座、四个脚轮、桌板下的托架和横梁。
  - 碰撞体全部是静态盒体或凸包，purpose 为 guide。桌面碰撞体是一个盒体，顶面就在 top_z，和可见表面重合。
- **`background.usda` `/Background`**：地毯地面（从 p4 中一块干净的 0.6 m 区域按地面单应性矫正，真实尺度，镜像平铺；亮度乘 0.67，因为照片像素本身已带有室内光照）、天花板（2.8 m，挡住 RoboDojo 默认的棕色摄影棚 HDR）以及四面墙（`/Background/Walls`：纯色饰面和门、白板、电视，见上一节）。房间家具和 G1-D 在 `/Background/Furniture`；G1-D 的网格在单独的二进制层 `usd/g1d.usdc`（约 1.2 MB），由 `Furniture/g1d_0` 引用并放到位。
- **`lights.usda` `/Lights`**：4 块吊顶面光（RectLight 1.2 × 0.6 m，6500 K，强度 24000），加环境光 Dome（150，被封闭的房间挡住，基本不起作用）。按 p3 照片标定：Isaac 相机没有白平衡，原先的 5000 K 加上棕色 HDR 从房顶灌进来，画面明显偏黄（地毯 R/B 1.29，照片 1.06）；强度扫了 6000 / 12000 / 24000 三档，取桌面亮度最接近照片的一档。

## 接入 RoboDojo

1. 把本目录整体拷到服务器 `Assets/Room/real_scene3/`。`layout_manager.select_room` 会加载目录下唯一的 `.usd`，也就是 `real_scene3.usd`。
2. 在评测布局里去掉 `Table`、`Ground`、`Background`，换成：

```json
"Room": {"default": "real_scene3", "default_pos": [0.0, -0.257, 0.0], "default_ori": [1, 0, 0, 0],
         "scale": [1, 1, 1], "collision": false, "table_height": 0.749}
```

   - `default_pos` 的 y = −0.257 把桌面前沿放到 RoboDojo 默认桌沿 y = −0.60。
   - 走线盒在远端中间，离机器人一侧桌沿 0.50–0.62 m，基本超出 G1 手臂在桌面高度的可达范围；它是桌面贴图，没有单独的几何体。
3. **机器人站位。** 桌下从前沿往里有 0.63 m 的空间（到挡板为止），两根立柱之间宽 1.22 m，所以 G1-D 按默认站位（根节点 y = −0.73）不会碰到桌腿；`check_scene.py` 按站立圆柱 r = 0.22 m 检查通过。
4. **高度。** 桌面比 real_scene1 的升降桌（0.68 m）高 0.069 m。用升降柱补偿（`LZ_mt_Joint`、`LZ_it_Joint` 各约 0.035），物体整体抬高 +0.069 m，这样和机器人的相对位置与办公室场景一致。
5. 灯光放在 Room 里，多环境并行时每个环境各有一套，和 real_scene1/2 是同一个问题。
