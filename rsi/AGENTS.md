# RSI：生成对抗式自我提升协议（v0.2，2026-10-24）

给定**模型**、**可用训练资源**和**评测平台**，在 RoboDojo（dual X5）上做多轮"生成数据 → 训练 → 对抗评测"的迭代，提高模型的泛化能力。本文件是所有参与这件事的 coding agent 的最高规则；和别的文档冲突时以本文件为准。目标与消融设计见 Notion「生成对抗式 RSI」。

核心思想是课程式学习：数据方像老师，按学生的薄弱科目出课程，循序渐进；评测方像考官，按学生水平调整试卷难度，防止偏科。两方互相对抗，互不通信。

## 一、三条硬规则

### 规则 1：官方评测资产必须保留，生产数据时一律不用

凡是出现在 RoboDojo 官方评测布局（`Eval_Layout/RoboDojo/arx_x5/0`，54 个任务）里、但不在官方训练数据里的资产，都是 **T0 官方保留资产**，任何训练数据都不许用。官方训练数据只覆盖 34 个基础任务，场景全是同一房间、同一桌面、没有干扰物。

| 资产 | 总数 | T0（官方保留） | 训练能用的现成资产 |
| :-- | :-- | :-- | :-- |
| 房间 `Assets/Room` | 14 | 12（全部被 `_random` 用掉） | 只有基础任务的 `Simple_Room`、`Simple_Room_nolight` |
| 桌面 / 地面 MDL 材质 | 504 | 372 | 基础任务的 2 种 + 评测从没用过的 130 种 |
| 杂物（干扰物） | 193 个实例 / 95 类 | 192（`_random` 191、`general_pickup` 145） | 1 个 |
| 任务物体实例 | — | `_random` 独有的 95 个 | 基础任务配置里的训练侧编号 |
| 背景 HDR | 1 | 0（基础任务也用它） | 这 1 张 |

（2026-10-24 在 `5090-2` 统计官方资产得到；以 `rsi/assets/t0.json` 为准，由裁判生成，见第五节。）

推论：只靠现成资产，房间和干扰物这两项几乎没有可随机的空间。要做泛化，就必须**造新资产**（第三节）。这也正是规则 1 的用意：不能拿考题来复习。

官方 seed 0 评测集本身也属于 T0：只在第 0 轮（基线）和最后一轮（终评）由裁判各跑一次，两个 agent 都看不到它的逐回合结果。

### 规则 2：只能做泛化，不能押题、抄答案

- **不抄答案**：训练布局不许复用任何考场布局或官方布局里的物体位姿（同一任务、同一物体、位置差 < 2 cm 且朝向差 < 5° 视为复用）。生成器从不读评测布局的位姿，只读它的结构（有哪些物体、标签、父子关系）。
- **不押题**：数据方看不到考卷内容，只能看到按科目汇总、分档的 Score 和保留率（第四节）。每一轮数据里至少 30% 要花在**边际探索**上：沿某个泛化维度往当前还没覆盖、也没有考过的方向扩展（第三节的算子），而不是只补成绩差的那几门。
- **可审计**：每批数据都要带 `report_<任务>.json`（每个布局抽到了什么）和覆盖统计。裁判按规则 1、规则 2 逐条检查，不通过的整批作废，不进训练。

### 规则 3：两个 agent 对抗，互不通信

- **数据方**（Data Agent）负责改进生产数据；**评测方**（Exam Agent）负责改进评测。两方的目标相反：评测方要找出模型做不好的地方，数据方要让模型在没见过的考卷上做得好。
- 两方之间没有任何直接通道：不共享 worktree、运行目录、聊天记录、记忆或 Notion 页面，不读对方的文件。唯一的交互是经过**裁判**（Referee）转交的、规定格式的信息（第四节）。
- 裁判不是 agent，而是确定性的脚本加人工审核。它负责训练、跑考试、检查规则、发布成绩和保管 T0。

## 二、角色与权限

| | 数据方 | 评测方 | 裁判 |
| :-- | :-- | :-- | :-- |
| 能用的资产 | T2 训练池 | T1 考场池 + T2（考场可以包含训练分布内的题） | 全部 |
| 布局 seed 段 | 1000–4999（`split=train`） | 5000–8999（`split=val`） | 9000–9999 封存探针；0 官方 |
| 能看到 | 本方数据、本方自测结果、裁判发布的成绩单、当前模型（只能在 T2 上自测） | 本方历届考卷和逐回合结果（含视频）、当前模型 | 全部 |
| 看不到 | 考卷、考场资产、逐回合考试结果、官方结果 | 训练数据、数据方的方案和计划 | — |
| 产出 | 数据集（经裁判审计）、新的 T2 资产 | 本轮考卷（布局 + 科目标注）、新的 T1 资产 | 训练后的模型、成绩单、审计报告 |
| 工作区 | 自己的 worktree + 运行目录 `rsi-<名>/data/` | 自己的 worktree + 运行目录 `rsi-<名>/exam/` | 运行目录 `rsi-<名>/referee/` |

隔离的落实方式（v0.1）：两方在 GPU 服务器上用不同的 Unix 用户，运行目录互相没有读权限；T0、T1 资产只链接进本方的 `Assets/` 覆盖目录。两方都不能改裁判的脚本和本文件，要改协议得由人来改。

## 三、泛化算子（"探索边际"可以用的操作）

两方都用同一套算子，区别只在于用的资产池不同（数据方用 T2，评测方用 T1）。每个算子对应一个"科目"维度，都可以分级。

| 维度 | 算子 | 现有工具 | 需要补的 |
| :-- | :-- | :-- | :-- |
| 物体位姿 | 在任务配置的范围内重采样；把范围往外扩一级 | `scripts/datagen/x5_layouts.py` | 越界扩展要先确认专家还能解 |
| 物体实例 | 同类别换实例；造新实例（形状、尺寸、颜色、材质变体） | 平台物体登记 + `scripts/objects/SKILL.md`；运行时换色、缩放 | X5 任务的新实例资产 |
| 干扰物 | 数量 0 → 5 → 10 → 20；类别；摆放密度 | `x5_layouts.py`（`clutter`） | **新杂物**：现成的 193 个里 192 个是 T0 |
| 房间 | 换房间 | `x5_layouts.py`（`rooms`） | **新房间**：现成的全部是 T0 或基础房间；可以用没用过的 130 种材质给 `Simple_Room` 换墙面做变体，或者导入 Real2Sim 场景 |
| 桌面 / 地面材质 | 从材质池里抽 | `x5_layouts.py`（`tables`、`grounds`） | 130 种可用材质要按 7:3 分给 T2 和 T1 |
| 光照 | 额外灯光的类型、数量、亮度、色温；HDR 亮度 | `x5_layouts.py`（`lights`、`background`） | 新 HDR；默认亮度要调低（10-23 有过曝） |
| 相机 | 头部相机角度扰动 | `x5_layouts.py`（`camera.ori_deg`） | 不许平移：平移 2 cm 会让部分环境出图全黑 |
| 指令 | 同义改写、换说法、加无关信息 | `desc_manager` 支持多模板随机 | 各任务的 `instructions.json` |
| 恢复 | 从模型失败的状态接管，让专家演示怎么救回来（DAgger） | `scripts/datagen/collect.py` | X5 专家；从任意状态起步的接口 |

**分级**：每个维度从 L0（和官方训练数据一样）到 L3（远超训练分布）分四级，具体取值写在 `rsi/subjects.yaml`（见第五节，v0.1 先由人定）。一个"科目" = 任务族 × 维度 × 级别。

**边际探索**：数据方每一轮至少 30% 的回合，要放在本方此前从没生成过的"维度 × 级别"组合，或者用本方新造的资产。评测方每一轮至少 30% 的考题，要放在此前从没考过的组合上。两方的探索方向都只能根据本方自己的历史来定，不能猜测对方。

## 四、信息流（裁判转交的唯一内容）

**给数据方的成绩单**（每轮一份，`referee/out/data/scorecard_r<N>.json`）：

```json
{"round": 3, "model": "OpenWAM@r3",
 "subjects": [{"task_family": "stack", "axis": "clutter", "level": 2, "n": 40, "score": "20-25", "retention": "0.4-0.5"}],
 "capability": [{"task": "push_T", "n": 30, "score": "0-5"}],
 "sealed_probe": {"score": "15-20", "retention": "0.3-0.4"},
 "audit": {"accepted": true, "rejected_batches": []}}
```

只给分档的 Score（每 5 分一档）、保留率（每 0.1 一档，见下面"难度怎么调"）和回合数。不给布局、视频、资产 id、失败原因，也不给官方成绩。回合数少于 30 的科目不发布。

**给评测方的**：每轮新模型的推理服务地址（黑盒，只能跑本方考卷），加上本方上一轮考卷的完整逐回合结果。不给训练数据和数据方的任何信息。

**评测方交给裁判的考卷**（`exam/out/exam_r<N>/`）：布局目录（`split=val`），每个布局都标注科目（任务族、维度、级别）。考卷要满足：
- 每个科目、每个级别至少 30 个回合，各维度都要覆盖，不许只考某一门（防偏科）；
- 每道题都必须可解：v0.1 用布局的物理合法性检查和"不超出 `subjects.yaml` 的范围"来近似，有了 X5 专家以后改成专家能解才算。

**难度怎么调**（v0.2，按 10-24 的仿真榜单修订，原来用"成功率高于 80% 升级、低于 20% 降级"）：

- **指标用 Score，不用成功率**：用任务判据给出的 0–100 部分完成分（`_result.json` 的 `score`，和榜单排名一致）。基线模型的成功率太低：OpenWAM-α 总成功率 11.92%，泛化随机版只有 4.11%；Pi-05 分别是 6.93% 和 1.44%。成功率在这个区间，阈值判断全是噪声。
- **按每个任务自己的 L0 做锚点**：每份考卷拿 15% 的回合考 L0，也就是和官方训练数据同样的条件。某个科目在级别 k 的**保留率** ρ = 该级别的平均 Score ÷ 同一任务的 L0 平均 Score。升降级看 ρ，不看绝对分数。
- **升降规则**：
  - ρ 的 95% 置信下界 ≥ 0.7，算"已掌握"，下一轮升一级；
  - ρ 的 95% 置信上界 < 0.3，算"太难，已经没有区分度"，降一级；
  - 其余情况保持不变。每轮最多动一级，置信区间用 bootstrap 估计。
  - 0.7 和 0.3 的依据：完整的 `_random` 相当于四个维度同时开到高级别，保留率在 OpenWAM-α 上是 0.25、Pi-05 0.28、最好的纯策略 VPP2 0.40、Simate-beta 0.73；智能体系统 WorldScape-R²SI 0.84、HexaShell-Preview 0.81。所以 0.3 大约是基线模型面对完整随机时的水平，0.7 大约是目前最好的系统。
- **回合分配**：60% 放在"前沿级别"（ρ 落在 0.3–0.7 之间的最高级别），25% 放在前沿的上一级，15% 放在 L0 锚点。
- **能力缺口任务不参与调难度**：L0 平均 Score 低于 10 的任务（按榜单，OpenWAM-α 有 15 个左右，例如 `push_T`、`align_blocks`、`solve_equation`、`play_Xylophone`），说明模型连本身都不会做，谈不上泛化。这类任务只放在成绩单的 `capability` 里，每轮固定考 30 个 L0 回合，难度不调；把它们补上是数据方的事。

## 五、每一轮的流程（裁判执行）

```
第 0 轮（准备）：
  读配置 rsi.yaml → 统计 T0（rsi/assets/t0.json）→ 把剩余资产按 7:3 随机分成 T2 / T1（固定种子，写 rsi/assets/split.json）
  → 用 T1 资产建封存探针（seed 9000–9999，建好就不再改，两个 agent 都看不到）
  → 官方 seed 0 基线评测（只此一次，结果只给人看）

第 r 轮（r = 1..R）：
  1. 评测方：拿到模型 M_{r-1} → 出考卷 exam_r
  2. 裁判：在 M_{r-1} 上跑 exam_r 和封存探针 → 发布成绩单 r 给数据方、逐回合结果给评测方
  3. 数据方：拿到成绩单 r → 生成数据 D_r（布局、专家采集、恢复数据）
  4. 裁判：审计 D_r（规则 1、2，第六节）→ 按固定配方训练 → M_r
  5. 记录：M_r 的封存探针成绩、各科目成绩、数据量、算力，写进 referee/ledger.jsonl

最后：官方 seed 0 终评（只此一次）
```

训练配方（数据混合比例、步数、学习率）在第 0 轮定好，之后不变。数据方只管数据，不调训练超参，这样各轮之间的比较才有意义。

封存探针是衡量"模型到底有没有在泛化"的标准，"RSI 轮数 → 泛化"的曲线就用它来画。考卷成绩只用来驱动对抗，因为考卷每轮都在变，不能直接拿来比较。

**消融**（Notion 里列的三项）都通过配置切换：
- `mode: generate_only`：评测方在第 1 轮出完考卷后冻结，之后每轮用同一份考卷；
- `rounds`：2、4、6、8；
- `models`：换基模。

## 六、裁判的审计清单（数据进训练前必须全部通过）

1. 布局和数据里没有任何 T0、T1 资产（检查房间、材质、HDR、杂物的类别和编号、物体实例）。
2. 没有复用考场布局或官方布局里的位姿（阈值见规则 2）。
3. 布局都在数据方的 seed 段内，`split.json` 标为 train。
4. 边际探索占比 ≥ 30%，按 `report_<任务>.json` 统计。
5. 每个回合都通过任务插件的验收；按 `scripts/datagen/SKILL.md` 完成导出、审计和回放一致性检查。
6. 新资产要登记来源：数据方造的进 T2，评测方造的进 T1。由裁判比对新资产和 T0、T1 资产的相似度（v0.1 先人工看渲染图），过于相似的不收。

## 七、输入配置

复制 `rsi/rsi.example.yaml`，填好以下三部分：要迭代的模型（策略目录、checkpoint、动作类型）、训练资源（主机别名、GPU、每轮时长上限、训练命令）、评测平台（主机别名、可用 GPU、仿真环境）。文件里只写 SSH 主机别名，不写地址和凭据。
